**Что уже есть**
- Локальный AI-workspace с агентным циклом: модель получает системный промпт, предлагает JSON-команды, команда исполняется в пределах workspace, результат возвращается в контекст. Это ядро видно в [src/main.py](/G:/programming/py/local/babkacli/src/main.py), [src/utils/commands.py](/G:/programming/py/local/babkacli/src/utils/commands.py), [src/ui/agent_worker.py](/G:/programming/py/local/babkacli/src/ui/agent_worker.py).
- Три основных поверхности: файловое дерево, встроенный редактор, чат с историей и терминал. Это уже близко к базовому “IDE + agent” сценарию в [src/ui/agent_studio_window.py](/G:/programming/py/local/babkacli/src/ui/agent_studio_window.py).
- Ограничение на действия агента по режимам `ask` и `agent`, то есть есть простая модель безопасности/политики команд.
- Локальное хранение сессий чата в `.babka/chats`, что дает persistence между запусками.
- Есть работающий embedded terminal на Windows и отдельный механизм рендера чата в HTML.

**Чего нет относительно Cursor**
- Семантического редактирования по выделению, мульти-курсора, inline-edit/“apply patch” UX.
- Нормального diff/review workflow: нет визуального сравнения изменений, принятия/отклонения правок, патчей на уровне хунков.
- Индексации репозитория и поиска по коду на уровне символов, файлов, ссылок и связанных сущностей.
- Интеграции с LSP/IDE-фичами: go to definition, references, rename, diagnostics, code actions.
- Контекстного понимания проекта: сейчас контекст в основном строится из текущего чата и ручных файловых операций, а не из системного индекса.
- Мультифайловых “agent edits with verification” как первоклассного workflow: есть команды, но нет удобного контроля изменений и автоматической валидации после правки.
- Нормальной модели доверия для выполнения команд: сейчас это просто workspace sandbox + JSON протокол, без явного “approve before write/run” слоя.
- Кроссплатформенной зрелости на уровне Cursor, особенно если целиться в единый стабильный desktop experience.

**Что даст максимальный прирост за 2-3 итерации**
1. **Добавить diff/patch-first workflow.**
   Самый большой прирост даст не новая UI-обертка, а возможность показать изменения до записи, подсветить хунки и дать кнопки accept/reject. Это сразу приближает проект к Cursor-подобному ощущению и снижает риск слепых перезаписей.

2. **Сделать индекс проекта и поиск по контексту.**
   Минимально: индекс файлов, быстрый full-text search, выбор релевантных файлов в контекст агента. Это резко улучшит качество ответов и уменьшит зависимость от ручного `ls/readfiles`.

3. **Встроить verify loop после изменений.**
   После `writefile/createFiles/runpy` агент должен автоматически предлагать проверку: тесты, lint, запуск целевых скриптов, и показывать результат рядом с правкой. Это превратит проект из “чат, который может править” в “агент, который завершает задачу до рабочего состояния”.
